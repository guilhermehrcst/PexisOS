# ADR 0001: v0.2 offline detector architecture

- **Status:** accepted for v0.2 research milestone (issue #2)
- **Date:** 2026-10-15
- **Supersedes:** nothing. v0.1 (`pexislink.core`) is retained, frozen, as a comparator.

## Context

The v0.1 detector (PR #1) compares later coolant readings with an earlier,
context-matched median. The audit ([AUDIT-v0.1.md](../AUDIT-v0.1.md))
reproduced, with tests, defects that make its outputs untrustworthy on routine
telemetry: a frozen sensor is `normal` forever (F-01); every cold start and every
legitimate load increase is a confirmed anomaly (F-02); "sustained" is a sample
count that bridges a 28-day gap (F-03); sensor sentinels become anomalies (F-04);
one duplicate row aborts the whole fleet (F-08); oversized input crashes or
exhausts memory (F-09, F-10).

Constraints from issue #2: Python 3.11+, CPU only, modest RAM, no mandatory
dependencies or services, deterministic, read-only, explicit evidence states,
labels never reach the model, no claims beyond what the evidence supports.

## Decision

### 1. Five stages, each a small module with one responsibility

| Stage | Module | Contract |
|---|---|---|
| Ingestion and validation | `ingest.py` | Bounded read (bytes, line length, rows). Closed schema: exact header, no duplicates, no unknown columns. Row syntax only: RFC 3339 timestamp with offset, ASCII decimal numbers, restricted vehicle-id alphabet. Fatal *file-level* problems raise `InputError`; *row-level* problems become issue codes on a `Record` so every input row still gets exactly one output. |
| Time and data-quality semantics | `quality.py` | Per-vehicle streaming state, O(1) memory per vehicle. Integrity: `accepted`, `duplicate`, `conflicting_duplicate`, `out_of_order`, `unplaceable`. Segments (gap > `segment_gap_s`), warm-up transient, physical plausibility ranges, stuck-sensor suspicion. The same annotations feed both the reference builder and the detector, so the rules cannot drift apart. |
| Reference model | `reference.py` | Frozen per-vehicle, per-context robust statistics (median, 1.4826·MAD floored at sensor resolution) from clean, warm, plausible reference samples only. Never updated from observations. |
| Detection | `detect.py` | Four statuses: `normal`, `suspected_anomaly`, `confirmed_anomaly`, `insufficient_evidence`, always with machine-readable reason codes. Two independent barriers (below). Time-based confirmation. |
| Offline evaluation | `synth.py`, `evaluate.py`, `baselines.py`, `benchmark.py` | Deterministic synthetic scenarios with ground truth returned *separately* from the rows; event-level metrics with confidence intervals; identical splits for every detector. |

The two-pass CLI (`detect`) validates the observation file completely
(structure, limits, chronology) before emitting the first assessment, so an
invalid run never produces partial output.

### 2. Semantics that replace v0.1 behaviour

- **Confirmation is a duration, not a count.** A run of same-direction
  deviations is confirmed when it has lasted `confirm_s` and no two consecutive
  deviating samples are more than `run_gap_s` apart. Context changes do not
  reset the run (the residual is already context-normalised); unassessable
  samples are neutral, but cannot bridge more than `run_gap_s`. Validation
  enforces `run_gap_s < confirm_s`, which guarantees at least three deviating
  samples per confirmation.
- **Warm-up is a transient, not an anomaly.** For `warmup_s` after a segment
  start the relative comparison is suppressed (`insufficient_evidence`,
  reason `warmup_transient`). The first observation of every vehicle is treated
  as a segment start because engine state before it is unknown.
- **Sensor validity before engine inference.** Values outside physical ranges
  are `implausible`, never anomalies. A reading that is identical across an
  engine-off gap of `stuck_gap_s` and stays identical, or that is flat for
  `flatline_s`, is `coolant_stuck_suspected`: the detector abstains instead of
  asserting `normal`.
- **Integrity issues are quarantined per record**, not fleet-wide: exact
  duplicates and late rows are excluded and reported; a conflicting duplicate
  also resets the vehicle's evidence run. Overlapping reference/observation
  periods remain a fatal error (leakage guard preserved from v0.1, now checked
  in a pre-pass and again per record).
- **Dispersion-aware threshold:** `|delta| >= k_scale * scale` where `scale` is
  the context's robust spread floored at `scale_floor_c` (1 C = OBD-II coolant
  resolution, so MAD = 0 on quantised data cannot produce a zero threshold).
- **Optional operating-load context:** if `engine_load_pct` is present in both
  files, it joins the context key. Without the signal, a legitimate load
  increase is not identifiable and this is reported, not hidden.

### 3. Defence in depth: two barriers with different premises

| Barrier | Premise | Fails when |
|---|---|---|
| Relative (context-matched, self-referenced) | the vehicle's own warm, valid past is normal | reference contaminated (F-07); unseen vehicle/context; unobserved confounder |
| Absolute high limit (`absolute_high_c`, reference-free) | physics: coolant persistently >= 115 C is abnormal for a liquid-cooled road engine | moderate faults below the limit; sensor reads low |

The absolute barrier can only raise an anomaly; it never asserts `normal`.
**Common-cause failure:** both barriers read the same coolant sensor. A
drifting or stuck sensor defeats both; the stuck-sensor rule is a third,
sensor-validity barrier, but **drift cannot be separated from a real
temperature change without a redundant signal** (none in this schema).

### 4. Pre-registered defaults (fixed before the held-out benchmark)

| Parameter | Value | Rationale |
|---|---|---|
| `segment_gap_s` | 900 | >15 min without data: engine may have cooled |
| `warmup_s` | 900 | typical warm-up 5-15 min in mild weather; deliberately *not* tuned for cold climates (tested as an assumption violation) |
| `stuck_gap_s`, `stuck_min_samples` | 3600, 5 | after >=1 h off, coolant cannot read identically for 5 samples of a restart |
| `flatline_s` | 2700 | 45 min bit-identical readings |
| plausibility ranges | coolant [-40, 150] C, rpm [0, 10000], speed [0, 300] km/h, load [0, 100] % | OBD-II PID ranges / physical limits |
| context bins | 500 rpm, 20 km/h, 25 % load | v0.1 bins kept for comparability; load bins coarse |
| `min_reference_samples` | 30 | v0.1's 5 gives a very noisy median and no usable spread |
| `k_scale`, `scale_floor_c` | 4.0, 1.0 C | threshold >= 4 C; v0.1 used 8 C |
| `absolute_high_c` | 115 C | above normal regulated range under heavy load |
| `run_gap_s`, `confirm_s` | 90, 300 | evidence must be continuous; 5 min filters short hill-climb transients |

### 5. Pre-registered hypotheses for the benchmark

- **H1** v0.2 raises fewer false alerts than v0.1 on normal operation.
- **H2** v0.2 recall on abrupt anomalies is not lower than v0.1's, and drift
  is detected at a smaller bias.
- **H3** Without a load signal, legitimate load increases produce false alerts
  in every relative detector; with the signal, v0.2 avoids most of them.
- **H4** v0.2 reduces false reassurance (`normal` during a stuck sensor).
- **H5** Unseen vehicles: v0.2's relative barrier abstains (no `normal` claims).
- **H6 (expected negative)** If warm-up in the cold lasts longer than
  `warmup_s`, v0.2 false alerts increase.
- **H7 (expected negative)** A fault present during the whole reference
  period is missed by every relative detector.

### 6. Amendment before the held-out run (2026-10-15)

The first development-split run showed v0.1 "detecting" sensor drift at a
median bias of 0.14 C, 0.5 min after onset: physically impossible. Event-level
recall credits any confirmed alert inside an event window, and v0.1 alarms at
almost every cold start, so its "detections" were coincidental (the harness
test already showed that an always-alarm detector gets recall 1.0). This was a
flaw in the *metric*, not in a detector. Before the test split was run:

- a **placebo control** was added to `evaluate.py`: every anomaly window is
  copied onto fault-free control vehicles and scored identically;
- **H2 is restated** in placebo-controlled terms: v0.2's *excess recall*
  (recall minus placebo recall) is at least v0.1's, for abrupt anomalies and
  for drift. Bias at detection is still reported, but only as evidence.

No detector parameter, scenario or other hypothesis was changed.

## Alternatives rejected

- **Fixing `core.analyze` in place.** It would destroy the comparator and make
  "v0.2 is better than v0.1" unmeasurable. Instead its decision rule is frozen
  and pinned by characterisation tests; only crash/misread/exhaustion bugs in
  its reader were fixed.
- **ML models (isolation forest, autoencoders, gradient boosting).** No labelled
  real data exists to justify them; each adds dependencies and opacity, and any
  gain on our own synthetic generator would be circular.
- **Sorting observations in memory.** Gives event-time semantics but O(n)
  memory and hides arrival-order problems. Replay in file order with explicit
  `out_of_order` is O(1) per vehicle and keeps the problem visible.
- **Fleet-pooled reference for unseen vehicles.** Inter-vehicle thermostat
  variation (several C) would be read as anomalies; needs measured
  inter-vehicle variance first. Unseen vehicles abstain instead.
- **Streaming service / message bus / database.** No requirement; offline
  research only.
- **pytest / hypothesis / numpy.** Standard-library `unittest` with seeded
  random property tests keeps the dependency graph empty.

## Consequences

- Output schema changes (`pexislink.assessment.v2`); the v0.1 CLI invocation
  still works unchanged, with a deprecation notice on stderr.
- Stricter input: files v0.1 accepted (unknown columns, lenient numerals, odd
  identifiers) are rejected by `detect` with a precise message.
- v0.2 abstains much more often. Coverage is reported next to every accuracy
  metric so that abstention cannot be mistaken for accuracy.
- Known residual risks are listed in [BENCHMARK.md](../BENCHMARK.md#limitations).
