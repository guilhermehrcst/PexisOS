# Benchmark: method, held-out results, scientific validity, limitations

> **Read this first.** All data here is synthetic and was generated by the same
> project that wrote the detector. The benchmark *verifies* behaviour against
> documented assumptions, including deliberate violations of them. It is **not**
> evidence of real-world accuracy, and nothing here predicts failures.

Generated results: [`reports/benchmark-full-test/report.md`](../reports/benchmark-full-test/report.md)
(held-out test split) and [`reports/benchmark-quick/`](../reports/benchmark-quick/)
(development split, reproduced byte-for-byte in CI). Every number below comes
from `reports/benchmark-full-test/results.json`.

## 1. Protocol

**Data.** `pexislink synth` simulates 8 vehicles per scenario with
thermostat-regulated coolant, warm-up from ambient after each park, load- and
heat-dependent rise, idle fan cycling, AR(1) sensor noise, 1 C quantisation,
multi-regime driving (idle, urban, highway) with hills, and 1-3 trips per day.
Each vehicle has 10 reference days followed by 20 evaluation days, sampled every
30 s (60 s in one stress variant). Its constants are assumptions listed in
`src/pexislink/synth.py`. It is not a validated engine model.

**Scenarios (12).** Normal operation (negative control); abrupt cooling failure
and stuck-open thermostat; gradual sensor drift (0.3-1.0 C/day, both signs);
legitimate load increase (false-positive condition); hot and severe-cold seasons
(false-positive condition and deliberate assumption violation); unreliable
sensor (5 % missing, 0.4 % spikes/sentinels, frozen sensor); vehicles without
any reference and references lacking highway driving; data-integrity noise
(duplicates, conflicting duplicates, late rows, mixed UTC offsets);
contaminated reference (fault during the last 30 % or the whole reference
period); and noise ×2 / 60 s sampling stress variants.

**Separation and leakage controls.**

| Risk | Control | Evidence |
|---|---|---|
| Labels used as inputs | Ground truth returned separately; detectors receive rows only; detection modules cannot import `synth`/`evaluate` | `tests/test_architecture.py` (verified by injecting a violating import) |
| Future information in the reference period | Injections draw from an independent random stream, so reference rows are byte-identical to the no-injection control | `CausalityTests` in `tests/test_synth.py` |
| Temporal overlap | Reference period strictly before evaluation, per vehicle; overlap is a fatal error (checked twice) | `ChronologyTests`, `test_leakage_*` |
| Cross-vehicle leakage | References are per vehicle; unseen vehicles are never given another vehicle's reference | metamorphic `test_vehicle_isolation`; H5 |
| Tuning on the test set | Parameters and hypotheses fixed in ADR 0001 before any run; seeds split once (dev 101-105, test 201-210) and never mixed | `test_seed_splits_are_disjoint`; ADR §4-6 |
| Identical splits | Every detector scores the same rows of the same datasets | `benchmark.run_benchmark` |
| Metric credits coincidence | **Placebo control** (event windows copied to fault-free vehicles) | `test_placebo_control_exposes_coincidental_detection` |

**Detectors.** `fixed-limit-115C` (naive warning light), `v0.1-as-shipped`,
`v0.1-cleaned` (oracle-free cleaning gives v0.1 the benefit of the doubt),
`v0.2`, and four single-factor ablations: `no-warmup`, `fixed-8C` (v0.1's
threshold), `no-load`, `no-absolute`.

**Metrics.** Event recall with Wilson 95 % intervals; **placebo recall**; alert
precision; false alerts per 1000 operating hours with exact Poisson intervals;
detection delay in operating minutes; coverage (share of rows with a status
other than `insufficient_evidence`); false reassurance (share of frozen-sensor
rows reported `normal`). N/A means not applicable, never zero.

**Amendment.** The development split showed v0.1 "detecting" drift at 0.14 C
of bias, 0.5 min after onset, which is physically impossible: v0.1 alarms at
almost every cold start, and raw recall credits any alarm inside an event
window. The placebo control was added and H2 restated before the test split
was run. No detector parameter changed (ADR 0001 §6).

### Hypotheses (verdicts computed mechanically)

| | Claim | Verdict | Key evidence |
|---|---|---|---|
| H1 | v0.2 raises fewer false alerts than v0.1 on normal operation | **supported** | 0 [0, 1.99] vs 5527 [5420, 5635] per 1000 h |
| H2 | placebo-controlled: v0.2 detects abrupt anomalies and drift at least as well as v0.1 | **supported** | v0.2 recall 1.0 with placebo 0.0; v0.1 recall 1.0 with placebo 1.0 (no demonstrated detection) |
| H3 | without a load signal, load increases cause false alerts; with it v0.2 avoids most | **supported** | v0.2 0 [0, 1.99] vs v0.2-no-load 41.5 [32.7, 51.8] per 1000 h |
| H4 | v0.2 reduces false reassurance under a frozen sensor | **supported** | 0.058 vs v0.1 0.814 (fixed limit 0.948) |
| H5 | unseen vehicles: v0.2 never reports `normal` | **supported** | 0 normal rows |
| H6 | (expected negative) severe cold outlasts `warmup_s` and raises v0.2 false alerts | **observed** | 45.2 vs 0 per 1000 h; mechanism checked below |
| H7 | (expected negative) a fault present during the whole reference period is missed by the relative barrier | **observed** | full contamination 0/20 (partial 20/20) |

### What the ablations show

| Component | Measured benefit | Measured cost |
|---|---|---|
| Warm-up suppression | false alerts on normal operation 1056 → 0 per 1000 h; it is the dominant fix | coverage 0.86 → 0.43 (the first 15 min of every trip are unassessed) |
| Dispersion-aware threshold (vs fixed 8 C) | drift recall 0.76 → 1.0, median bias at detection 7.75 → 4.04 C; abrupt delay 25.5 → 13.7 min | hot-season false alerts 0 → 61 (the 4σ threshold also sees ambient heat) |
| Engine-load context | load-change false alerts 41.5 → 0 per 1000 h | coverage 0.49 → 0.43 (0.49 → 0.23 while towing); delay at 60 s sampling 29.6 → 54.7 min |
| Absolute 115 C barrier | **none measured**: v0.2 and v0.2-no-absolute are identical in every scenario | none measured |
| Stuck-sensor rule (not ablated; v0.1 comparison) | false reassurance 0.81 (v0.1) → 0.058 (v0.2) | abstention while suspected |

### Findings against this implementation

1. **The absolute barrier earned nothing here.** Injected faults rarely hold
   ≥ 115 C for the 300 s confirmation. On the 10 overheating vehicles without
   any reference, v0.2 detected 0; the naive 2-sample fixed limit detected 1
   (seed 203, Δ = 19.2 C). Its ~10 lines are kept only because they were
   pre-registered and cost nothing measurable; changing them now would be
   tuning on the test set. A lower limit or a shorter confirmation for this
   barrier needs evaluation on a fresh split.
2. **Hot ambient is the largest false-alert source, not the one predicted.**
   H6 named cold warm-ups. A direct check of the 84 seasonal false alerts
   (seeds 201-205) shows both mechanisms. Cold-season alerts are all *below*
   reference and fire 20-21 min into a trip, just after the 15 min window
   ends: the predicted warm-up overrun. Hot-season alerts (61 of 84) are all
   *above* reference and spread through the trip: ambient heat acting as an
   unobserved confounder.
3. **Abstention is the price of zero false alerts.** v0.2 is silent on 57 % of
   rows in normal operation and 78 % in the unseen-vehicle scenario. Coverage
   is reported next to every accuracy number for that reason.
4. **Contamination is fundamental.** With a fault present during the entire
   reference period, the relative barrier learns it as normal (0/20).
5. **v0.1's alarms are cold starts.** 94 % of v0.1's alert onsets (930 of 989
   on seed 201) begin in the first 15 min of a trip, which is why doubling the
   sensor noise leaves its false-alert count unchanged (10,265 in both).
6. **Drift is detected late and only once large.** Median operating delay 438
   min (about 163 h of wall time), at a median bias of 4.0 C. A 1 C/day drift
   reaches 4 C in 4 days.

## 3. Scientific validity

**What was detected.** Sustained deviations of the coolant reading from the
same vehicle's warm, context-matched reference, in synthetic data whose
physics we wrote: abrupt cooling faults within a median of 13.7 operating
minutes, stuck-open thermostats, and sensor drift once it exceeds about 4 C,
with zero false alerts in every condition except seasonal ambient shifts, and a
placebo recall of zero. That is a statement about *internal consistency* with
the documented assumptions.

**What was not predicted.** Nothing. No result here forecasts a failure,
estimates time-to-failure or remaining useful life, or shows that any anomaly
corresponds to a mechanical defect. A deviation can be a sensor fault (drift was
injected as one and was detected exactly like an engine fault), a confounder
(hot ambient) or a real defect; the detector cannot tell them apart.

**What would prove predictive value with real data.**

1. Real, licensed fleet telemetry with **independently labelled failure events**
   (workshop records with failure dates and components), not anomaly labels.
2. Splits by **vehicle** and by **time**: models frozen before the evaluation
   period, evaluated on vehicles never seen in development.
3. A pre-registered lead-time target and the **distribution** of alert lead
   times before failures, versus alert rates in failure-free periods
   (placebo windows), with confidence intervals.
4. Comparison against base rates and simple baselines on identical splits;
   calibration if probabilities are claimed.
5. Evidence that alerts precede failures **causally** rather than through
   confounders (season, duty cycle, maintenance schedules).

## 4. Real datasets: status

Reaching `archive.ics.uci.edu`, `data.nasa.gov` and `www.nasa.gov` was **blocked
by this environment's network policy** (HTTP 403 from the proxy), so no real
data was downloaded, inspected or licence-checked. No experiment was simulated
in its place. For the record, neither candidate would validate *this* detector:
Scania APS (UCI) is anonymised histogram features for **fault classification**,
with no timestamps or coolant/rpm/speed series, so it supports neither lead time
nor RUL. NASA C-MAPSS is **simulated turbofan** run-to-failure data for RUL
research, not automotive telemetry. A future optional experiment should live in
a separate module, download on demand (never in CI), pin the archive by SHA-256,
record the licence, and keep fault classification, anomaly detection and RUL
strictly separate.

## 5. Reproducibility

~~~bash
PYTHONPATH=src python -m pexislink benchmark --profile quick --out reports/benchmark-quick   # ~40 s, dev seeds
PYTHONPATH=src python -m pexislink benchmark --profile full  --out reports/benchmark-full-test  # ~5 min, test seeds
~~~

- `results.json` is deterministic: the quick profile produced the same SHA-256
  (`cfa56aa7…`) on CPython 3.11.17, 3.12.3 and 3.13.16; CI regenerates it and
  fails on any difference.
- Determinism was verified on one platform (Linux x86-64, glibc 2.39). It is not
  verified across operating systems or libm implementations.
- `provenance.json` records versions, a SHA-256 of the package sources, timings
  and peak memory.

## 6. Resources (single host; all runs CPU-only)

| Run | Constraint | Result |
|---|---|---|
| Full held-out benchmark (10 seeds × 12 scenarios × 8 detectors, 2.6 M evaluation rows) | 1 CPU (`taskset -c 0`), 1 GiB address space (`prlimit --as`) | 274 s wall, 271 s CPU, peak RSS 75 MB |
| Quick benchmark (CI) | none | about 40 s, peak RSS 55 MB |
| `pexislink detect` on 834k rows (37 MB CSV, 200 vehicles) | 1 CPU, 1 GiB | 26 s, peak RSS **77 MB** (171 MB before replacing `io.StringIO`, whose UCS-4 buffer quadrupled memory) |
| `pexislink detect` on 9.3 MB CSV | 1 CPU, 1 GiB | 6 s, peak RSS 33 MB |

Memory is the input snapshot (about 1.35 × file size, capped at 64 MiB per file)
plus O(vehicles) state plus the reference statistics; observations are streamed.
Throughput (benchmark stage timings, same rows): v0.2 strict parsing runs at
about 139,000 rows/s and detection at about 177,000 rows/s, so about 78,000
rows/s end to end. v0.1 on cleaned input, including its own lenient parsing,
runs at about 157,000 rows/s. **v0.2 is roughly 2× slower than v0.1**; that is
the price of strict validation and the quality layer.

## Limitations

- Synthetic data written by the same author as the detector: structural
  knowledge of the generator cannot be excluded by seed splits. Assumption
  violations (cold, contamination, unseen vehicles) reduce but do not remove
  this circularity.
- One sensor. Drift and real temperature change are indistinguishable, and both
  barriers share the coolant sensor (common-cause failure).
- Unobserved confounders (hot ambient; load without a load signal) cause false
  alerts; v0.2 can abstain only when the confounding signal exists.
- Time-based warm-up halves coverage (0.86 → 0.43) on 15-55 min trips, costs
  more on short trips, and is too short in severe cold.
- A single far-future timestamp glitch makes all later rows of that vehicle
  `out_of_order` (fail-safe and visible, but it removes coverage).
- Parameters are a-priori research defaults, not validated limits. The
  absolute barrier had no measured benefit.
- Determinism is verified on one platform only. GitHub Actions are pinned by
  tag, not commit SHA.

## Recommendations for the next milestone

1. Obtain licensed real telemetry with workshop-confirmed failure dates; repeat
   this protocol with vehicle and time holdouts before any predictive claim.
2. Add ambient temperature as an optional context signal and re-measure the hot
   season (the largest remaining false-alert source).
3. Replace the fixed warm-up window with a physics-based warm-up end (e.g.
   reaching the vehicle's own regulated band), evaluated for the stuck-open
   thermostat risk it introduces.
4. Re-evaluate the absolute barrier (limit, confirmation time) on a fresh split,
   or remove it.
5. Add a redundant signal (oil or intake temperature) to separate sensor faults
   from engine behaviour.
6. Pin GitHub Actions by commit SHA; test determinism on macOS and Windows.
