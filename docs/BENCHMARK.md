# Benchmark: method, results, scientific validity, limitations

> **Read this first.** All data here is synthetic and was generated by the same
> project that wrote the detector. The benchmark *verifies* behaviour against
> documented assumptions, including deliberate violations of them. It is **not**
> evidence of real-world accuracy, and nothing here predicts failures.

Generated reports: [run 2, test seeds](../reports/benchmark-full-test/report.md),
[confirmation, unused seeds](../reports/benchmark-confirm/report.md) and
[quick, development seeds](../reports/benchmark-quick/report.md) (CI regenerates
the quick results on Python 3.11 and compares them byte for byte). Numbers in
§2 and §3 come from the `results.json` beside each report. Numbers marked *error analysis* come from
`scripts/error_analysis.py`, which explains results and changes nothing.

## 1. Protocol

**Data.** `pexislink synth` simulates 8 vehicles per scenario with
thermostat-regulated coolant, warm-up from ambient after each park, load- and
heat-dependent rise, idle fan cycling, AR(1) sensor noise, 1 C quantisation,
multi-regime driving (idle, urban, highway) with hills, and 1-3 trips per day.
Each vehicle has 10 reference days followed by 20 evaluation days, sampled every
30 s (60 s in one stress variant). The constants are assumptions listed in
`src/pexislink/synth.py`; it is not a validated engine model.

Which vehicle plays which role (faulty or control) is drawn per seed, so a
vehicle id carries no label information. In scenario descriptions, `v0`-`v7`
are role slots, not vehicle ids. A vehicle's driving is shared across scenarios
(paired design), so the per-scenario totals count the same driving 16 times:
each run has **1,857 unique operating hours**, not the 29,656 that the scenario
totals add up to.

**Scenarios (16).** Ground-truth labels are used only for scoring.

| Group | Scenarios | What is injected |
|---|---|---|
| Negative control | `normal_operation` | nothing |
| Faults to detect | `abrupt_anomaly`, `gradual_sensor_drift`, `stress_subtle_overheat` | cooling failure (+12-22 C at idle, weaker at speed) and stuck-open thermostat (-12 to -20 C at highway speed, 40 % of that at idle), to be detected within 24 h; sensor drift of 0.3-1.0 C/day in either sign; overheat of only 3-7 C |
| False-positive conditions | `load_change`, `seasonal_shift` | towing (+20-35 % load, legitimately hotter); hot (+15-20 C) or severe-cold (-25 to -30 C) ambient |
| Sensor and data faults | `unreliable_sensor`, `stress_stuck_flicker`, `data_integrity` | 5 % missing readings, 0.4 % spikes and sentinels, frozen sensors (in one variant flickering by 1 LSB); duplicates, conflicting duplicates, late rows and mixed UTC offsets, with overheats |
| Assumption violations | `unseen_vehicles_and_regimes`, `contaminated_reference`, `stress_slow_warmup_x0.6`, `stress_slow_warmup_x0.5` | vehicles without a reference, or without highway driving in it; a fault already present in the last 30 % or all of the reference period; warm-up heating at 0.6× and 0.5× |
| Robustness | `stress_noise_x2`, `stress_abrupt_noise_x2`, `stress_sampling_60s` | twice the sensor noise; 60 s sampling |

**Detectors.** All of them receive telemetry rows only, and all score the same
rows of the same datasets.

- `fixed-limit-115C`: a naive warning light, ≥ 115 C on 2 consecutive samples.
- `v0.1-as-shipped`: frozen v0.1 on raw rows. The run fails if v0.1 rejects any row.
- `v0.1-cleaned`: frozen v0.1 after cleaning that uses no labels, which gives
  v0.1 the benefit of the doubt.
- `v0.2` with its defaults.
- Six single-factor ablations: `no-warmup`, `fixed-8C` (v0.1's threshold),
  `fixed-4C` (a plain threshold without the robust scale), `no-load`,
  `no-absolute` and `no-stuck`.

**Metrics.** Definitions are in `src/pexislink/evaluate.py`.

- **Detected event**: a confirmed anomaly in the fault's direction (overheat
  above the reference, stuck-open thermostat below it, drift in the sign of its
  rate) within the fault's horizon: 24 h for abrupt faults, the end of
  evaluation for drift.
- **Placebo recall**: the same windows and directions applied to fault-free
  control vehicles. **Excess recall** = recall - placebo recall. A detection
  claim needs an excess-recall interval above 0.
- **Alerts**: maximal same-direction runs of confirmed rows within a trip. A
  true alert starts inside a fault interval in the right direction. True alerts
  have no horizon, so a late alert can be true without detecting its event. A
  misdirected alert starts inside a fault interval in the wrong direction. A
  false alert starts outside every fault interval.
- **False alerts** per 1000 *eligible* operating hours (outside fault
  intervals), and the share of eligible trips with at least one false alert.
- **Coverage**: the share of rows whose status is not `insufficient_evidence`,
  overall and on the rows affected by each nuisance condition.
- **False reassurance**: the share of rows during a sensor fault reported `normal`.
- **Delay**: time from onset to the first detecting row, in operating minutes
  (parked time excluded), per fault kind.
- **95 % intervals**: bootstrap over vehicles (1000 resamples, fixed seed). For
  zero false alerts, the exact Poisson upper bound is given; it assumes
  independent alerts. N/A means not applicable, never zero.

**Leakage and separation controls.**

| Risk | Control | Evidence |
|---|---|---|
| Labels used as inputs | Ground truth is returned separately and runners receive rows only. Detection modules cannot import `synth`, `evaluate` or `benchmark`. | `tests/test_architecture.py` |
| Labels recoverable from ids | Fault roles are drawn per seed. | `test_fault_roles_are_drawn_per_seed` |
| Future information in the reference | Injections draw from an independent random stream, so reference rows are byte-identical to the no-injection control. | `CausalityTests` |
| Temporal overlap | Per-record `reference_overlap` quarantine against the last contributing reference sample. | `test_reference_overlap_is_quarantined_per_record` |
| Cross-vehicle leakage | References are per vehicle. A vehicle without one never borrows another's. | `test_vehicle_isolation`; H5 |
| Metric credits coincidence | Direction-aware, horizon-bounded placebo control. | `test_detection_delay_and_placebo`, `test_horizon_and_direction_are_enforced` |
| Degenerate verdicts | Coverage floor and per-trip conditions, checked against a silent and an always-alarm detector. | `HypothesisCriteriaTests`, `test_oracle_null_and_always_alarm` |
| Tuning on the test set | Defaults were written before any data existed (ADR §4). After run 1, only defect fixes changed them (`stuck_tolerance_c` added, the flatline rule removed, the coolant range widened; ADR §7); none was tuned to results. Seeds were split once. **Weakness:** run 2 reused the test seeds, so a confirmatory run on unused seeds was declared before running (§8). | `test_seed_splits_are_disjoint`; ADR §4, §7, §8 |

### 2.4 Findings against this implementation

1. **Silence is the price of zero false alerts.** Coverage is 0.43 in normal
   operation, 0.28 with an unreliable sensor, 0.23 in the unseen-vehicle
   scenario and 0.04 while towing. Coverage is reported next to every accuracy
   number for that reason.
2. **The zero-false-alert result depends on the warm-up window.** *Error
   analysis:* every v0.2 false alert in run 2 began 20.0-49.7 min into a trip,
   never earlier than the 15 min warm-up window plus the 5 min confirmation. All 27
   cold-season and all 120 slow-warm-up alerts were below the reference and
   began 20.0-25.4 min into the trip: warm-up overrun, the mechanism H6
   predicted. All 64 hot-season alerts were above the reference and began
   20.1-49.7 min into the trip (median 25.2): ambient heat acting as an
   unobserved confounder.
3. **v0.2 is fragile to the sampling rate.** At 60 s, recall falls from 0.9 to
   0.56 and coverage from 0.43 to 0.31. Two parameters are in effect counts of
   samples. `min_reference_samples = 30` means 15 min of reference at 30 s but
   30 min at 60 s. `run_gap_s = 90` tolerates up to two missing samples at
   30 s (with the generator's ±3 s timestamp jitter, about half the time) and
   none at 60 s. *Error analysis* on development seeds 101-105, with no default
   changed: at 60 s, a minimum of 15 samples raises recall from 0.76 to 0.84
   (coverage 0.32 to 0.41), and also allowing a 150 s gap raises it to 0.88. At
   30 s, the same seeds give 0.96. This is the class of defect that F-03 fixed
   for persistence, still present in two parameters.
4. **Subtle faults are mostly missed.** v0.2 detects 10/50 overheats of 3-7 C
   (confirmation: 6/50). The `fixed-4C` ablation detects 16/50 (17/50),
   including every event v0.2 detects (paired sign test p = 0.03 and 0.001),
   and `fixed-8C` 0/50 (0/50). v0.1 itself has excess recall 0.27 [0.08, 0.44]
   (confirmation: 0.07), because its warm-up-contaminated reference lowers its
   medians, at a cost of 5625 false alerts per 1000 h.
5. **Abrupt faults that were missed were detected late, not never.** *Error
   analysis:* v0.2 confirmed all 5 abrupt events it missed (of 50) after the
   24 h horizon (confirmation: 1 missed, also confirmed later). Inside the
   window, most rows were in warm-up or in contexts without a reference, and no
   evidence run lasted more than 234 s of the required 300 s. On three of them
   v0.2 reported `normal` on 1, 7 and 11 rows while the fault was active. The
   generator makes overheats weaker at speed, a likely cause that was not
   checked row by row. False reassurance is scored only for sensor faults, so
   this is the closest measured analogue for anomalies.
6. **The absolute barrier earned nothing measurable, because the benchmark
   barely exercises it.** Overheats add 12-22 C at idle to a regulated
   temperature near 90 C, and less at speed. Within the horizon, the naive
   two-sample 115 C limit detected 2 of 40 events in `contaminated_reference`,
   1 of 30 in `data_integrity` and none elsewhere (confirmation: 1, 1 and
   none). *Error
   analysis:* in the unseen-vehicle scenario, no overheat produced two
   consecutive readings ≥ 115 C within 24 h of onset. The benchmark therefore
   cannot measure the barrier's benefit; its behaviour is verified only by unit
   tests (`test_stuck_high_sensor_still_alarms`,
   `test_readings_above_150_c_are_alarms_not_implausible`).
7. **The load context buys abstention, not discrimination.** H3 holds only by
   abstention in both runs. In run 2 the load context lowered recall in 5 of 8
   fault scenarios (abrupt 0.92 to 0.9, noise ×2 0.9 to 0.88, unseen 0.45 to
   0.35, subtle 0.28 to 0.2, 60 s sampling 0.76 to 0.56) and changed nothing in
   the other 3. *Error analysis*, pairing the same events: the cost is
   significant only at 60 s sampling, where 10 events (confirmation: 8) were
   detected only without the load context (exact sign test p = 0.002 and
   0.008). Elsewhere no paired difference is significant (p > 0.2), and in the
   confirmation's `data_integrity` the load context detected one event more.
   Whether to keep it is an open decision.
   Deciding it on these seeds would be tuning on the test set, so it is a
   recommendation below.
8. **No capability on vehicles without a reference.** *Error analysis:* v0.2
   detected 0 of the 10 overheats on vehicles without any reference. All 10
   are "missed without evidence": v0.2 abstained and never said `normal`. On
   vehicles whose reference lacked highway driving, it detected 7/10. Its
   excess recall (0.35) equals v0.1's.
9. **Contamination is fundamental.** With the fault present during the whole
   reference period, v0.2 detected 0/20: it learned the fault as normal.
   v0.1-cleaned confirmed 13/20 of those, inside a flood of 5654 false alerts
   per 1000 h; its overall excess recall here is 0.6, against 0.47 for v0.2.
10. **Drift is detected late, and only once it is large.** The median delay is
    509.8 operating minutes (173 h of wall time) at a median bias of 4.07 C;
    the maximum is 784 operating minutes. With one coolant sensor, drift and a
    real temperature change cannot be told apart, and both barriers read the
    same sensor (a common-cause failure).
11. **v0.1's alarms are cold starts.** *Error analysis:* 9,641 of v0.1's 10,265
    alert onsets in normal operation (93.9 %) began in the first 15 min of a
    trip (median 2.6 min; confirmation 93.2 %). That is why doubling the sensor
    noise barely changes its false-alert count (10,265 and 10,265 in run 2;
    10,026 and 10,013 in the confirmation).

run 2's intervals might suggest. Read single-run numbers with their intervals.

- Abrupt-fault recall rose from 0.9 to 0.98, but the median overheat delay
  doubled from 14.0 to 28.3 operating minutes (stuck-open thermostat: 7.5 to
  11.5). No interval is computed for delays, and they are clearly unstable
  across seed sets.
- Subtle-overheat recall fell from 0.2 to 0.12 [0.04, 0.22], while the plain
  4 C threshold reached 0.34 [0.21, 0.48]. The marginal intervals touch, but
  the paired comparison is clear: the plain threshold detected every event
  v0.2 detected, plus 11 more (exact sign test p = 0.001).

  most one event, in either direction: subtle 0.12 against 0.14, noise ×2 0.88
  against 0.9, and `data_integrity` 0.87 against 0.83 in favour of the load
  context; abrupt, drift, unseen and contaminated were equal.
- Unseen-vehicle recall rose from 0.35 to 0.45. Again, all 10 overheats on
  vehicles without any reference were missed without evidence.
- Cold-season false alerts fell from 27 to 11 and hot-season alerts rose from
  64 to 70. Slow warm-up ×0.5 gave 119 (run 2: 116).

*Error analysis on seeds 301-310* (`scripts/error_analysis.py confirm`): the
mechanisms of §2.4 replicate. All 11 cold-season and all 122 slow-warm-up
false alerts were below the reference and began 20.1-24.7 min into a trip; all
70 hot-season alerts were above it and began 20.1-44.1 min into a trip. 93.2 %
of v0.1's alert onsets in normal operation began in the first 15 min of a
trip. The one missed abrupt event (an overheat of 12.8 C) was confirmed after
the horizon. No overheat in the unseen-vehicle scenario produced two
consecutive readings ≥ 115 C within 24 h of onset.

## 4. Scientific validity

**What was detected.** In synthetic data whose physics we wrote, v0.2 detects
sustained deviations of the coolant reading from the same vehicle's warm,
context-matched reference: abrupt cooling faults within a median of 14.0
operating minutes in run 2 and 28.3 in the confirmation, stuck-open
thermostats within 7.5 and 11.5, and sensor drift once it exceeds about 4 C.
It had zero false alerts in normal operation and placebo recall 0 in every
scenario of both runs. It raised false alerts when its warm-up assumption
or the absence of ambient confounders was violated. It abstains on most rows.
These are statements about *internal consistency with the documented
assumptions*.

**What was not predicted.** Nothing. No result here forecasts a failure,
estimates time to failure or remaining useful life, or shows that an anomaly
corresponds to a mechanical defect. A deviation can be a sensor fault (drift
was injected as one and is detected exactly like an engine fault), a
confounder (hot ambient) or a real defect, and the detector cannot tell them
apart.

**What would prove predictive value with real data.**

1. Real, licensed fleet telemetry with **independently labelled failure
   events** (workshop records with failure dates and components), not anomaly
   labels.
2. Splits by **vehicle** and by **time**: models frozen before the evaluation
   period, evaluated on vehicles never seen in development.
3. A pre-registered lead-time target, and the **distribution** of alert lead
   times before failures against alert rates in failure-free periods (placebo
   windows), with confidence intervals.
4. Comparison against base rates and simple baselines on identical splits;
   calibration if probabilities are claimed.
5. Evidence that alerts precede failures **causally** rather than through
   confounders such as season, duty cycle or maintenance schedules.

## 5. Real datasets: status

Reaching `archive.ics.uci.edu`, `data.nasa.gov` and `www.nasa.gov` was **blocked
by this environment's network policy** (HTTP 403 from the proxy), so no real
data was downloaded, inspected or licence-checked, and no experiment was
simulated in its place. Neither candidate would validate *this* detector
anyway. Scania APS (UCI) is anonymised histogram features for **fault
classification**, with no timestamps and no coolant, rpm or speed series, so
it supports neither lead time nor RUL. NASA C-MAPSS is **simulated turbofan**
run-to-failure data for RUL research, not automotive telemetry. A future
optional experiment should live in a separate module, download on demand
(never in CI), pin the archive by SHA-256, record the licence, and keep fault
classification, anomaly detection and RUL strictly separate.

## Limitations

- **Circularity.** The detector and the generator were written by the same
  author, so seed splits cannot exclude structural knowledge of the generator.
  Assumption violations (cold, contamination, unseen vehicles, slow warm-up)
  reduce this circularity but do not remove it.
- **Test-seed reuse.** Run 2 reused the test seeds after the review changes.
  The confirmation is one run on 10 unused seeds of the same generator; it
  checks against overfitting to particular seeds, not against overfitting to
  the generator.
- **Paired design.** The 16 scenarios reuse the same driving, so they are not
  independent replications. The intervals are marginal per detector; the
  ablation comparisons were not analysed as paired differences.
- **One sensor.** Drift and a real temperature change are indistinguishable,
  and both barriers read the same sensor (a common-cause failure).
- **Unobserved confounders.** Hot ambient, and load without a load signal,
  cause false alerts. v0.2 can abstain only when the confounding signal exists.
- **Time-based warm-up.** It halves coverage (0.86 to 0.43), costs more on
  short trips, is too short in severe cold, and hides faults that show
  themselves during warm-up (finding 5).
- **Parameters that depend on the sampling rate.** `min_reference_samples` and
  `run_gap_s` (finding 3).
- **Subtle faults** (3-7 C) are mostly missed (finding 4).
- **The absolute barrier is unexercised** by the generator (finding 6).
- **Late conflicting duplicates** are not detected; conflict detection depends
  on arrival order (review L8).
- **A sensor that freezes mid-drive** is suspected only after the next
  engine-off gap.
- **A single far-future timestamp glitch** in the observations makes all later
  rows of that vehicle `out_of_order`. This fails safe and is visible in the
  summary, but it removes coverage.
- **`suspected_anomaly` is never scored.**
- **Parameters are research defaults** chosen a priori, not validated limits.
- **Determinism is verified on one platform only.** GitHub Actions are pinned
  by tag, not by commit SHA.

## Recommendations for the next milestone

1. Obtain licensed real telemetry with workshop-confirmed failure dates, and
   repeat this protocol with vehicle and time holdouts before any predictive
   claim.
2. Express the reference minimum as time and the evidence gap relative to the
   observed sampling interval; evaluate on fresh seeds (for example 401-410).
3. Add ambient temperature as an optional context signal and re-measure the
   hot season.
4. Replace the fixed warm-up window with a physics-based end of warm-up (the
   vehicle reaching its own regulated band), evaluated for the stuck-open
   thermostat risk that this introduces.
5. Re-evaluate the load context (abstention against recall) and the absolute
   barrier, with a generator that exercises it, on fresh seeds. Remove what
   does not earn its place.
6. Add a redundant signal (oil or intake temperature) to separate sensor
   faults from engine behaviour.
7. Use paired statistics for ablations.
8. Pin GitHub Actions by commit SHA; test determinism on macOS and Windows.
