## 0. Scope and rationale

Build a strictly **file-to-file**, reproducible CAN/DBC decoding laboratory based on **synthetic classic-CAN logs** and a locally supplied DBC. This is a protocol-integration experiment, **not** vehicle acquisition, diagnosis, failure prediction, sensor validation, maintenance advice, or a way to connect to ECUs.

Stage A (this branch): **optional cantools-based offline replay only**.  
Stage B (separate branch/PR, **not** in this implementation): optional tsfresh experiments on causal rolling windows; further research must keep Scania Component X work and its labels isolated.

No device communication is permitted. Physical or virtual CAN interfaces, SocketCAN bus objects, ELM327 devices, OBD-II services, J1939 transport interactions, ECU requests, transmissions, writes and actuations are **out of scope**.

## 2. Proposed command and closed input contract

Target interface (adapt the CLI wiring cleanly to the actual repository):

```bash
pexislink lab can-replay --dbc synthetic.dbc --frames synthetic_can.csv --out replay.jsonl --summary replay.json
```

Input files are local regular files, never followed through symlinks. Both are required; there are no defaults that access a system CAN interface.

Frame CSV columns, **exactly** this order for Lab A:

```text
timestamp,arbitration_id,is_extended_id,data_hex
```

- `timestamp`: explicit RFC3339 offset or `Z`, finite supported year range; retain input order (including late/duplicate observations), record irregularities without silent reordering.
- `arbitration_id`: ASCII `0x` followed by 1 to 8 hexadecimal digits; numeric value from 0 through `0x1FFFFFFF`. Use the extended flag to disambiguate identical numeric IDs.
- `is_extended_id`: literal `0` (11-bit, ID <= `0x7FF`) or `1` (29-bit, ID <= `0x1FFFFFFF`). Reject out-of-range and mismatched combinations.
- `data_hex`: 0 to 16 hex digits, even length, **0 to 8 bytes**. No spaces, delimiters, RTR, error frames or CAN FD in v0.4 Lab A.
- Strict UTF-8/CSV, safe headers and bounded rows/records. No implicit casts, `NaN`, negative IDs, unrecognized columns, missing fields, malformed quotes or multiline records.
- The DBC is user-provided. Do not commit real OEM DBCs without clear redistribution permissions. **Synthetic tiny DBC** generated by this project is the only CI fixture. A message’s numeric identifier must not cause standard-vs-extended aliasing; verify with tests.
- Interpret signal names/units/scaling **only** when defined by the DBC. Do not invent vehicle identity, fault explanations, signal-to-component mapping or units for unknown bytes.

## 3. Output and failure semantics

Use a **small stable versioned schema** (`pexislink.can-replay.v1`) documented with examples.

A normal decoded record may include index, original timestamp, arbitration ID, extended flag, DBC message name, decoded signal names/units/values, and status `decoded`. A frame absent from the DBC must still produce a row with status `unknown_message`; a message with structurally valid frame but wrong expected payload length or other decode failure should produce `decode_error` with a stable code. Avoid leaking arbitrary exception contents.

**No dropped rows.** Exactly one output record per input data row **when the input CSV is structurally valid**. A malformed file causes a fail-closed run, no committed partial output. Preallocate temp outputs outside the input tree, parse/stream, fsync as practical, atomically replace outputs only when all checks pass, and clean up on exceptions or Ctrl-C. Define behavior if two output paths are identical or overlap either input. If a two-file atomic commit cannot be guaranteed, explicitly document partial-commit recovery and use a single authoritative manifest as a commit marker rather than claiming multi-file atomicity.

Include a deterministic summary: counts by status, number of frames, resource limits, anonymized provenance of local input bytes (SHA-256 without paths or payloads), tool and optional decoder version, exact data-dependent schema, no real VINs or location traces.

* Gate failures (input unreadable, too large, symlink, corrupt CSV, unsupported frame type, invalid DBC, changed file, output write error) must have distinct documented exit codes and avoid leaking local paths or unfiltered payload values to stderr.
* Default maximums should fit a memory-constrained CPU-only workstation. Bound frame-file bytes/rows/record length and DBC file size. Validate post-open identity, size and timestamps after reading; explicitly document filesystem race caveats.
* Keep numeric output deterministic and finite. Unknown frame IDs cannot silently turn into decoded signals. Never send a request, transmit a frame, create a CAN bus, or contact the network.

## 4. Architecture

```text
      local synthetic DBC             local synthetic CAN CSV
              |                                 |
       bounded read + hash              bounded CSV parse + hash
              |                                 |
      optional cantools decoder       validated immutable frame
              |                                 |
              +-------------+-------------------+
                            |
                deterministic row assessment
                    decoded | unknown_message | decode_error
                            |
               buffered/streamed temporary outputs
                            |
                 atomic result + audit summary
```

Design a narrowly scoped module under `pexislink` (e.g. `canreplay.py` and `lab_cli.py`) isolated from the v0.2 detector and the v0.3 `componentx` module. Import the optional decoder **inside the adapter**, not at package import time.

Default installation remains standard-library only: `pyproject.toml` should retain `dependencies = []`. If introducing `project.optional-dependencies`, choose and pin a tested cantools version, document its **complete transitive dependency and license graph** and CI strategy. Stub tests alone do not prove cantools integration.

The architectural AST/runtime tests currently forbid network/process creation. Extend them rather than weakening or deleting them. A read-only file decoder should pass these tests with optional dependency absent.

## 5. TDD validation matrix

Start with an independent, explicitly synthetic DBC with:
- one 11-bit and one 29-bit message with **the same numeric ID** to catch key collisions;
- unsigned/signed and scaled signals; correct unit provenance;
- explicit expected decoded values from a manually calculated oracle independent of cantools;
- unknown ID, wrong payload length, invalid hex, truncation, invalid CSV quoting, BOM, non-UTF8, oversized rows, oversized file, duplicate and out-of-order timestamps;
- DBC parse errors, missing optional dependency, unrecognized signal type, exceptional decoder outputs and nonfinite values;
- symlink and output alias attacks, input growth/same-size mutation, low resource caps;
- byte-identical runs and no network/device/subprocess activation.

Prefer **RED -> minimal fix -> GREEN** and document test coverage of each identified defect. A genuine integration smoke test must invoke the **actual installed cantools decoder** on synthetic DBC frames; if unavailable, clearly report `not_run`. Test Python 3.11, 3.12 and 3.13 in offline CI. Keep the v0.2 synthetic benchmark byte-identical; do not edit or regenerate its committed reports.

### Explicit isolation and scientific claims

1. Leave `core`, `ingest`, `quality`, `reference`, `detect`, `benchmark`, `componentx`, existing synthetic scenarios and committed benchmark results unchanged unless a tiny CLI/architecture-test change is reviewed.
2. Stage A **never** reads Scania labels, real vehicle data or files under an external account.
3. The ability to decode CAN frames is **not** evidence that a temperature reading is real, that a vehicle has a defect, or that an anomaly predicts any repair.
4. The eventual tsfresh Lab B must not blend sensor values across vehicle IDs, use future windows, or evaluate on the test labels while selecting transformations.
