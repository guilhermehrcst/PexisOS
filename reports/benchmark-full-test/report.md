# PexisLink benchmark (full profile, test split)

> Synthetic data generated by the same project that wrote the detector. These numbers verify behaviour against documented assumptions; they are not evidence of real-world accuracy and say nothing about failure prediction.

- Seeds: [201, 202, 203, 204, 205, 206, 207, 208, 209, 210]; 8 vehicles per scenario; 10 reference days then 20 evaluation days per vehicle.
- pexislink 0.2.0a0, Python 3.11.17, code sha256 `f4078c0d29b83994`.
- Intervals are 95 %: Wilson for proportions, exact Poisson for false-alert rates. N/A means not applicable (no events, no alerts, or no stuck-sensor rows), never zero.
- Delay is operating time (minutes of data) from event onset to the first confirmed anomaly.
- **Placebo recall**: the same event windows copied onto fault-free control vehicles. A detector that alarms often 'detects' placebos too; recall is evidence of detection only to the extent that it exceeds placebo recall. Delays and drift bias of a detector with high placebo recall are coincidental.

## Detectors

- `fixed-limit-115C`: naive warning light: >= 115 C for 2 consecutive samples; no reference, time or quality logic
- `v0.1-as-shipped`: frozen v0.1 rule on raw rows; the run fails if v0.1 rejects any row
- `v0.1-cleaned`: frozen v0.1 rule after oracle-free cleaning (drop unparseable rows, sort, de-duplicate)
- `v0.2`: pre-registered defaults
- `v0.2-no-warmup`: ablation: warm-up suppression off
- `v0.2-fixed-8C`: ablation: v0.1's fixed 8 C threshold instead of 4 x robust scale
- `v0.2-no-load`: ablation: engine-load context ignored
- `v0.2-no-absolute`: ablation: absolute 115 C barrier off
